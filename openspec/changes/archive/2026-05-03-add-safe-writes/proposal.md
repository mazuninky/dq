## Why

После M1 у `dq` есть полноценный read-стек, но любая попытка редактирования пока reject'ится с exit 6 (`-i/--diff/--backup` парсятся, но возвращают `InvalidInput`). Без write-команд `dq` не закрывает основной DevOps-сценарий — точечную правку k8s-манифеста, helm values, github-workflow, package.json в репозитории.

Round-trip safety — самый рискованный технический блок проекта (см. [dq-plan.md:343-361](../../../dq-plan.md)): всё после M2 (bulk-операции M3, fmt M4, новые форматы M5, автофиксы линтеров M10) зависит от того, что write через `dq` сохраняет комментарии, blank lines, порядок ключей, стиль кавычек, anchors, indent и числовую точность. M2 поднимает эту инфраструктуру и закрывает контракт двумя командами — `set` и `del`.

**Подход — textual-edit (span-based), не event-emitter rewrite.** Спайк по `saphyr` round-trip ([spikes/saphyr/RESULTS.md](../../../spikes/saphyr/RESULTS.md)) показал, что ни один pure-Rust YAML крейт не сохраняет комментарии на уровне tokens — scanner отбрасывает их до event stream'а ([saphyr issue #103](https://github.com/saphyr-rs/saphyr/issues/103) с января 2026, без roadmap'а). Custom emitter поэтому не способен восстановить то, чего нет в input'е. Подход M2: используем `saphyr-parser` исключительно для **structural discovery** — events с positions сворачиваем в `Pointer → ByteRange` span map; original bytes хранятся в `Document` нетронутыми. `Document::set_at` модифицирует только нужный span. Это ровно тот же подход, что `toml_edit` использует для TOML — и причина, почему TOML round-trip в экосистеме работает, а YAML — нет. Comments/blank lines/quote style survive просто потому что байты вокруг них никогда не переписываются.

## What Changes

- **Команды `set` и `del`** для YAML/JSON/TOML с типизированным JSON Pointer'ом. `set` принимает значение из аргумента, stdin или файла; `del` принимает только pointer.
- **Write-флаги активируются**: `-i/--in-place` (write back через atomic temp+rename), `--diff` (unified diff на stdout, без записи), `--backup` (`.bak` рядом с оригиналом перед записью). Без `-i` и без `--diff` write-команды пишут результат на stdout.
- **YAML round-trip через textual-edit**: добавляется парсер на `saphyr-parser` events, который при чтении строит `Pointer → ByteRange` span map (без NodeMetadata — бесполезно: scanner отбрасывает comments до events). `Document` хранит исходные `Vec<u8>` + span map. `set_at` переписывает байты в нужном span'е, оставляя всё остальное нетронутым. **Важно:** `serde_yml` остаётся для read-команд M1 (как parse-to-Value); новый saphyr-parser-based слой добавляется параллельно **только для write-pat**. Read-баseline M1 не ломаем.
- **TOML round-trip через `toml_edit`**: replaces `toml` крейт. `toml_edit` уже работает на span-edit принципе — это и есть proof, что подход правильный для structured config форматов.
- **JSON round-trip — собственный wrapper** поверх `serde_json`: сохраняет `IndexMap` key order, big-int как `String`, indentation style исходника. Опционально перевод на span-edit для consistent semantics с YAML/TOML — оценить в design.
- **Helm/Go-template guard**: препроцессор детектит `{{ }}` шаблоны до парсинга. По умолчанию `set`/`del` на templated YAML возвращают error с понятным сообщением и предлагают два escape-hatch: `--allow-templates` (best-effort, формат может сломаться) или `--raw-template-strings` (значения шаблонов трактуются как opaque строки). Молчаливый fallback не используется — он ломает agent-сценарии.
- **Atomic write на всех platform'ах**: `tempfile::NamedTempFile` в той же директории + `persist()` (использует `rename` на Unix, `MoveFileEx` на Windows). На Windows есть отдельный тест, потому что rename'ы поверх открытых файлов там работают иначе.
- **Big-int precision**: M1 уже хранит big-int как `BigInt(String)` literal text. M2 проверяет, что write через все три формата возвращает byte-exact ту же строку (в том числе для значений за пределами `i64`/`u64`/`f64` без потери).
- **Exit-code `WRITE_FAILED=7`** для случаев, когда parsing+resolution успешны, но запись провалилась (filesystem, permission, atomic rename collision на Windows). Текущие 0/1/2/3/4/5/6 остаются стабильными.
- **`-F` для write-команд**: при выводе на stdout (без `-i`) можно сменить формат через `-F json` — это работает как M1 `convert`, но через те же handler'ы. Для `-i` смена формата запрещена (file extension определяет формат записи).

**Что НЕ входит в M2** ([dq-plan.md:357](../../../dq-plan.md)): bulk-операции через glob (M3), `patch`/`merge` (M3), `diff` между файлами (M3), форматирующие флаги типа `--sort-keys`/`--quote-style` (M4), новые форматы (M5), линтеры (M8+), markdown (M9). `convert -i` — отложено до M3 вместе с остальным bulk-режимом, поскольку поведение `convert` по сути = "read in format A, write in format B" и в M2 контракт write фокусируется на сохранении исходного формата, а не на смене.

## Capabilities

### New Capabilities

- `data-query-write`: write-команды (`set`, `del`) — семантика операций, обработка отсутствующего pointer'а (`set` создаёт промежуточные узлы, `del` ошибается), exit-коды, write-флаги (`-i`/`--diff`/`--backup`), atomic write контракт, ограничение `-i` с `-F`.
- `template-guard`: детектирование Go-template синтаксиса (Helm/Argo) до парсинга, error по умолчанию с двумя escape-hatch (`--allow-templates`, `--raw-template-strings`), машиночитаемый error variant `TemplatedFile { detected_marker: String, line: u32 }`.

### Modified Capabilities

- `format-support`: добавляются требования round-trip preservation для YAML/TOML/JSON (комментарии, key order, quote-style, anchors/alias, blank lines, indent, big-int precision). Текущий `Format::write` контракт расширяется — реализации обязаны принимать `Document` со всеми metadata-узлами и эмитить эквивалентный текст. Парсеры заменяются: `serde_yml` → `saphyr`, `toml` → `toml_edit`, JSON получает собственный preservation wrapper. Read-only поведение M1 остаётся равноценным наблюдаемо (parse того же файла даёт ту же `Value`-проекцию через `Document::value()`).
- `cli-shell`: write-флаги (`-i`, `--diff`, `--backup`) перестают reject'иться через `Cli::reject_write_flags()` — этот helper удаляется. Добавляется требование atomic-write на всех platform'ах для `-i`. Добавляется новый exit-code constant `WRITE_FAILED = 7` в `pub mod exit_code` и mapping в `exit_code_for_error`. SIGPIPE/Reporter/non-interactive контракты M1 не меняются.

(Capabilities `data-query-read` и `path-syntax` не модифицируются — read-команды остаются как в M1, JSON Pointer уже поддерживает `set`/`del` через `resolve_mut` paths, добавляемые в `dq-core` под write-операции, но без изменения публичного контракта.)

## Impact

- **Code (новое)**: `crates/dq-core/src/document/spans.rs` (Pointer → ByteRange map + builder из saphyr events), `crates/dq-core/src/parsers/yaml_spans.rs` (saphyr-parser based span discovery, write-only path), `crates/dq-core/src/parsers/toml.rs` (заменяет text внутри — `toml_edit` API), `crates/dq-core/src/parsers/json.rs` (расширяется span-edit semantics), `crates/dq-core/src/template_guard.rs`, `crates/dq-core/src/atomic_write.rs`, `crates/dq-core/src/textual_edit.rs` (общие helpers — apply span replacement, compute insertion-region indent, etc.), `crates/dq-cli/src/commands/set.rs`, `crates/dq-cli/src/commands/del.rs`, `crates/dq-cli/src/cli/args/set.rs`, `crates/dq-cli/src/cli/args/del.rs`. `crates/dq-transform/src/lib.rs` остаётся placeholder.
- **Code (изменения)**: `crates/dq-core/src/document.rs` (Document расширяется полем `original_bytes: Vec<u8>` и `spans: SpanMap` для write-pat; read-pat через `value()` остаётся как был), `crates/dq-core/src/parsers/yaml.rs` (read-pat M1 на serde_yml — не трогаем), `crates/dq-cli/src/cli/args.rs` (удалить `reject_write_flags`, добавить subcommands), `crates/dq-cli/src/exit_code.rs` (`WRITE_FAILED = 7` + mapping), `crates/dq-cli/src/main.rs` (dispatch расширяется на set/del, ≤ 80 строк лимит остаётся).
- **Dependencies (новые)**: `saphyr-parser` (низкоуровневый event API; не путать с высокоуровневым `saphyr` — он не нужен), `toml_edit`, `similar` для unified diff. `tempfile` уже dev-only — переезжает в `dq-core` runtime deps.
- **Dependencies (удаляются)**: `toml` (стандартный) — `toml_edit` его заменяет. `serde_yml` остаётся (нужен для read-pat M1) — ignore в [deny.toml:69](../../../deny.toml) сохраняется до момента, когда (если когда-нибудь) read-pat будет унифицирован под saphyr-parser-based парсер. Это отдельный change post-M2.
- **Tests**: golden-runner расширяется на 30+ репрезентативных файлов из открытых проектов ([dq-plan.md:359](../../../dq-plan.md)) — k8s manifests с anchors+комментариями, helm charts, hugo frontmatter, github workflows. Round-trip property test (proptest) — генерация Document → write → parse → equal. Snapshot diff'ов на 10-15 типичных edit-сценариев. Новый Windows-CI job для atomic-write smoke (или явное skip с TODO до M6 — обсудить в design).
- **Backward compatibility**: M1 read-команды поведенчески не меняются. Snapshot'ы M1 для structured errors остаются валидными. CLI-флаги `-i/--diff/--backup` меняют поведение с "exit 6" на "выполнить операцию" — это intentional break контракта M1, но т.к. M1 явно эти флаги отвергал и в release notes M1 они описаны как "M2-deferred", это не считается regression.
- **Project meta**: `lefthook.yml` дополняется проверкой `cargo test --features round-trip` если фича будет (TBD в design). `deny.toml` — удалить ignore для serde_yml advisory. `dq-plan.md` правится в части Tech stack (saphyr/toml_edit фактически приходят в M2, не в M9).
